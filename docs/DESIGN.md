# 戰役模擬器（War Sim）— 文字版設計草案 v0.1

> 狀態：草案，待需求確認（見第 12 節「待確認問題」）
> 範圍：本文件只定義「做什麼」與「怎麼運作」，UI 視覺設計在需求確認後另行產出。

---

## 1. 產品定位

一個**網頁版**的歷史戰役模擬器：

- 在地圖上看到各方**兵團**與**兵種**的位置、兵力、狀態。
- 戰役**隨時間推進**：可播放、暫停、快轉、拖曳時間軸回看任一時刻。
- 第一個題材：**三國著名戰役**。之後可擴充到其他時代（架構不綁死三國）。

### 1.1 三種使用方式（由淺到深）

| 模式 | 說明 | 使用者能做什麼 |
|---|---|---|
| **A. 歷史重播** | 依史料／演義把戰役編成「劇本」，像看動態戰史地圖 | 播放、暫停、調速、拖時間軸、點兵團看資訊 |
| **B. 推演模擬** | 由模擬引擎依規則算出戰鬥結果，而非寫死 | 修改初始條件（兵力、將領、天氣）後看結果如何變化，例如「如果沒有東南風？」 |
| **C. 指揮對戰** | 玩家扮演一方下達命令，AI 或另一玩家扮演另一方 | 即時或回合制下令：移動、進攻、防守、火攻、撤退 |

建議順序：**A → B → C**。A 能最快做出成果並驗證地圖與時間軸；B 需要戰鬥規則；C 需要命令系統與 AI。

## 2. 核心概念（名詞表）

| 名詞 | 定義 |
|---|---|
| 戰役 Scenario | 一場完整戰役的資料包：地圖、陣營、兵團、初始狀態、事件、勝利條件 |
| 陣營 Faction | 例：曹魏、孫吳、劉備軍；有顏色、旗號 |
| 將領 General | 人物，有能力值與技能，可指揮一個兵團 |
| 兵團 Corps / Unit | 地圖上最小的可操作單位，由一位主將統領，包含一種或多種兵種 |
| 兵種 UnitType | 步兵、騎兵、弓弩兵、水軍…，決定移動、攻防、克制關係 |
| 地圖 Map | 地形、河流、道路、城池、關隘、渡口 |
| 時間 Tick | 模擬的最小時間單位 |
| 事件 Event | 在某時間或某條件下觸發的事情，例：「東南風起」「黃蓋詐降」 |
| 命令 Order | 對兵團下達的指令，例：移動到 X、攻擊 Y、駐守 |

## 3. 地圖系統

### 3.1 地圖表示方式（需決定，見待確認問題 Q4）

| 方案 | 優點 | 缺點 |
|---|---|---|
| **六角格 Hex** | 規則清楚、易算距離與地形、戰棋感 | 較抽象、不像真實地圖 |
| **連續座標 + 地形區塊** | 看起來像真實戰史地圖、移動平滑 | 路徑規劃與碰撞較複雜 |
| **真實地理底圖（經緯度）** | 可疊古今地名、教育價值高 | 需處理古今河道差異、底圖授權 |

**建議**：底層用「連續座標 + 隱藏的六角格/網格做地形查詢與尋路」，畫面上看起來是一張手繪風戰史地圖，兵團平滑移動。

### 3.2 地形類型

| 地形 | 移動成本 | 影響 |
|---|---|---|
| 平原 | 1.0 | 騎兵最有利 |
| 丘陵 | 1.5 | 防守方加成 |
| 山地 | 2.5 | 騎兵大幅受限，伏兵有利 |
| 森林 | 2.0 | 遮蔽視野，易遭火攻 |
| 沼澤 / 濕地 | 3.0 | 疫病風險（赤壁） |
| 河流 / 江 | 不可徒涉（需渡口或船） | 水軍專屬區 |
| 道路 | 0.7 | 行軍、補給加速 |
| 城池 / 營寨 | — | 大幅防禦加成，可囤糧 |
| 關隘 | — | 狹窄，限制同時交戰兵力 |

### 3.3 環境因素

- **晝夜**：夜間視野下降、夜襲加成。
- **天氣**：晴 / 雨 / 霧 / 雪；雨天火攻失效、弓弩下降。
- **風向與風力**：影響火攻蔓延方向與船隻速度（赤壁核心機制）。
- **季節**：影響疫病、河水漲落（水淹七軍）。

## 4. 兵種系統

### 4.1 基本兵種

| 兵種 | 移動 | 攻 | 防 | 射程 | 特性 |
|---|---|---|---|---|---|
| 步兵（槍／刀盾） | 中 | 中 | 高 | 近戰 | 守城、結陣 |
| 弓弩兵 | 中 | 中 | 低 | 遠 | 遠程壓制，近戰弱 |
| 騎兵 | 快 | 高 | 中 | 近戰 | 衝鋒、追擊、奇襲；山地／沼澤弱 |
| 輕騎 / 斥候 | 最快 | 低 | 低 | 近戰 | 偵察、擾糧 |
| 水軍（艨艟、鬥艦、樓船） | 水上快 | 中 | 中 | 近／遠 | 只能在水域；怕火 |
| 器械（衝車、井闌、投石） | 慢 | 攻城極高 | 低 | 遠 | 攻城用 |
| 特殊：虎豹騎、白馬義從、陷陣營、無當飛軍… | — | — | — | — | 戰役專屬精銳，以「兵種 + 加成」表示 |

### 4.2 克制關係（初版）

```
騎兵 ──克──▶ 弓弩兵
弓弩兵 ──克──▶ 步兵（遠距離時）
步兵(槍) ──克──▶ 騎兵
火攻 ──克──▶ 水軍、森林中的部隊、連環船
```

### 4.3 兵團狀態值

| 欄位 | 說明 |
|---|---|
| 兵力 strength | 目前人數 |
| 士氣 morale 0–100 | 低於門檻會潰逃；主將陣亡、被包圍、糧盡會大降 |
| 疲勞 fatigue 0–100 | 行軍、戰鬥累積；休息恢復 |
| 糧草 supply | 距離補給線太遠會下降，歸零士氣崩潰（官渡烏巢） |
| 陣型 formation | 行軍／方陣／魚鱗／鶴翼…（可延後實作） |
| 狀態 status | 行軍、交戰、駐守、潰逃、埋伏、渡河中 |

## 5. 將領系統

- 能力值：**統率**（影響士氣與陣型）、**武力**（單挑、近戰加成）、**智力**（計策成功率、識破計策）。
- 技能範例：`火計`、`伏兵`、`奇襲`、`水戰精通`、`鼓舞`、`看破`。
- 事件：主將陣亡／被俘 → 兵團士氣大跌；可選擇是否實作「單挑」。

## 6. 時間系統

### 6.1 雙層時間尺度

| 層級 | 單位 | 用途 | 範例 |
|---|---|---|---|
| 戰略層 | 天 | 大軍行軍、對峙、糧道 | 官渡對峙數月 |
| 戰術層 | 刻／時辰（建議 1 tick = 15 分鐘遊戲時間） | 實際交戰 | 赤壁火攻一夜 |

時間軸可在兩種尺度間自動切換：無交戰時快速跳過，有交戰時放慢。

### 6.2 播放控制

- ▶ 播放 / ⏸ 暫停 / ⏩ 1x·2x·4x·8x 速度
- 時間軸拖曳：跳到任一時刻
- 事件標記：時間軸上顯示關鍵事件（點擊跳轉）
- ⏪ 倒轉：靠「決定性模擬 + 定期快照」實作（見 9.3）

## 7. 模擬規則（模式 B / C 使用）

每個 tick 依序執行：

1. **事件觸發**：檢查時間／條件事件（風向改變、援軍抵達）。
2. **命令處理**：兵團依命令決定目標。
3. **移動**：依地形成本、疲勞、兵種速度移動；尋路（A*）。
4. **視野／偵察**：更新戰爭迷霧（可選）。
5. **交戰判定**：接觸範圍內的敵對兵團進入戰鬥。
6. **戰鬥結算**：
   - 基礎：類 Lanchester 模型，雙方每 tick 損失 ∝ 對方有效戰力
   - 有效戰力 = 兵力 × 兵種攻擊 × 克制係數 × 地形係數 × 士氣係數 × 疲勞係數 × 將領加成
   - 側翼／背後攻擊、包圍加成
7. **士氣更新**：損失比例、包圍、主將狀態、友軍潰逃連鎖。
8. **潰逃與追擊**：士氣 < 門檻 → 潰逃，被騎兵追擊損失加倍。
9. **補給更新**。
10. **勝利條件檢查**。

所有隨機數使用**固定種子**的亂數產生器，確保同樣輸入 → 同樣結果（重播、倒轉、分享都靠這點）。

## 8. 劇本（Scenario）資料格式

戰役以 JSON 描述，方便日後新增戰役甚至讓使用者自製。

```jsonc
{
  "id": "chibi-208",
  "name": "赤壁之戰",
  "date": { "start": "0208-11-01", "end": "0208-12-31" },   // 農曆/西曆需決定
  "map": "maps/chibi.json",
  "factions": [
    { "id": "wei", "name": "曹操軍", "color": "#1f4e8c" },
    { "id": "wu",  "name": "孫權軍", "color": "#b22222" },
    { "id": "shu", "name": "劉備軍", "color": "#2e7d32" }
  ],
  "generals": [
    { "id": "caocao", "name": "曹操", "lead": 96, "war": 72, "int": 91, "skills": ["鼓舞"] },
    { "id": "zhouyu", "name": "周瑜", "lead": 97, "war": 71, "int": 96, "skills": ["火計", "水戰精通"] },
    { "id": "huanggai", "name": "黃蓋", "lead": 78, "war": 83, "int": 70, "skills": ["詐降"] }
  ],
  "units": [
    {
      "id": "wei-fleet-1", "faction": "wei", "general": "caocao",
      "composition": { "navy": 80000, "infantry": 40000 },
      "position": [512, 300], "morale": 70, "supply": 60,
      "tags": ["連環船", "疫病"]
    }
  ],
  "environment": { "weather": "晴", "wind": { "dir": "NW", "force": 2 } },
  "events": [
    { "at": "0208-12-07T20:00", "type": "wind_change", "wind": { "dir": "SE", "force": 4 }, "text": "東南風起" },
    { "at": "0208-12-07T22:00", "type": "fire_attack", "by": "huanggai", "target": "wei-fleet-1", "text": "黃蓋火船詐降" }
  ],
  "script": [
    // 模式 A 使用：寫死的移動軌跡與結果（關鍵幀）
    { "unit": "wei-fleet-1", "keyframes": [ { "t": "0208-12-07T22:00", "pos": [512, 300] }, { "t": "0208-12-08T06:00", "pos": [430, 180], "strength": 30000 } ] }
  ],
  "victory": [ { "faction": "wu", "type": "enemy_rout", "target": "wei" } ],
  "sources": ["《三國志·周瑜傳》", "《資治通鑑》卷六十五"]
}
```

**重點**：`script`（關鍵幀）供模式 A 歷史重播；`events + 規則引擎` 供模式 B 推演。同一份劇本可兩者兼用。

## 9. 技術架構（建議）

### 9.1 技術選型

| 層 | 建議 | 理由 |
|---|---|---|
| 語言 | TypeScript | 前後端共用型別，模擬引擎可重用 |
| 前端框架 | React + Vite | 生態成熟，面板／時間軸 UI 好做 |
| 地圖渲染 | **PixiJS（WebGL）** 或 Canvas 2D | 上百兵團動畫流暢；SVG 在單位多時會卡 |
| 狀態管理 | Zustand | 輕量 |
| 模擬引擎 | 純 TS 模組，跑在 Web Worker | 不卡 UI，可單元測試 |
| 資料 | 靜態 JSON（劇本、地圖） | MVP 不需要後端 |
| 部署 | GitHub Pages / Vercel | 純靜態即可 |
| 後端（之後） | 只有在需要帳號、多人對戰、劇本分享時才加 | — |

### 9.2 模組劃分

```
war_sim/
├─ docs/                  設計文件
├─ packages/
│  ├─ engine/             模擬引擎（無 UI 依賴）
│  │  ├─ model/           型別：Unit, General, Map, Scenario…
│  │  ├─ systems/         movement, combat, morale, supply, events
│  │  ├─ rng.ts           固定種子亂數
│  │  └─ simulate.ts      step(state, orders) → newState
│  ├─ scenarios/          戰役資料（JSON）與地圖
│  └─ web/                前端
│     ├─ map/             地圖渲染、兵團圖示、動畫
│     ├─ timeline/        時間軸與播放控制
│     └─ panels/          兵團資訊、戰報、事件紀錄
```

### 9.3 時間回溯的做法

- 引擎是純函式：`state(t+1) = step(state(t), orders(t), rng)`。
- 每 N 個 tick 存一份快照；拖回時間軸時，找最近快照再往前算到目標時刻。
- 模式 A 的關鍵幀則直接內插（插值位置與兵力）。

## 12. 待確認問題

### 產品方向
- **Q1. 核心體驗**：主要是「看」（歷史重播，模式 A）、「推演」（改條件看結果，模式 B），還是「玩」（親自指揮，模式 C）？
- **Q2. 史實依據**：以《三國志》正史為主、《三國演義》為主，還是兩者可切換？（例：草船借箭、借東風屬演義）
- **Q3. 目標使用者**：自己玩／教學用（歷史課）／給一般玩家的遊戲？這會影響資訊密度與「遊戲感」。

### 地圖與視覺
- **Q4. 地圖風格**：六角格戰棋、手繪古地圖風、還是現代衛星／地形底圖疊古地名？
- **Q5. 兵團表現**：用北約軍事符號式的方塊圖示、旗幟 + 將領頭像、還是小兵人偶群？
- **Q6. 縮放層級**：需要從「全國戰略圖」一路縮放到「單一戰場」嗎？還是每場戰役一張獨立地圖即可？

### 模擬細節
- **Q7. 兵團粒度**：一個兵團大約代表多少人？（例：每團 5,000 人 / 每位將領一團）一場戰役大概同時顯示幾個兵團？
- **Q8. 時間精度**：以「天」為單位即可，還是需要細到「時辰」？
- **Q9. 戰爭迷霧**：要不要只顯示己方看得到的敵軍？
- **Q10. 將領單挑、計策**：要不要做？還是只保留能力值加成？

### 技術與範圍
- **Q11. 平台**：只要桌機瀏覽器，還是也要支援手機／平板？
- **Q12. 帳號與多人**：MVP 是否完全不需要後端（純前端）？
- **Q13. 語言**：只要繁體中文，還是需要簡體／英文？
- **Q14. 第一場戰役**：同意先做小戰役（街亭／定軍山）打底，還是直接挑戰赤壁？
